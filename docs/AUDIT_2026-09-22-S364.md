## A1 · Signup error responses crash

Confirmed from the production Worker log for POST /desk/dispatch/subscribe: `JSON_HEADERS is not defined`. A deliberately invalid request reproduced HTTP 503 with code `edge_handler_unavailable`, without sending email. `JSON_HEADERS` was declared inside the push-subscription handler but referenced by the separate public-form handler.

Fix: make the immutable response headers available to both handlers. Test the real Worker route, including malformed body, challenge configuration, missing/invalid challenge, email validation, success forwarding and upstream failure. Preserve CSRF, challenge verification and rate limits.

Restore that widget's existing secret to the affected Worker environments; do not rotate it, change domains, or weaken validation. Verify staging first, then production.

## A3 · The deployment verifier targets a sibling project

The old deploy-desk-dispatch projectRef() reads the shared SUPABASE_URL. Its no-send checks failed four endpoint assertions while direct invalid-input checks against the website's declared project succeeded. The member-newsletter deployer already documents and avoids this exact shared-slot mismatch.

Fix: pin and authorize the repository's declared project, make verification no-send by default, require an explicit valid --live-email argument for a real send, and test these boundaries. A reused recipient appearing in a historical provider log is not proof of current delivery.
