## 2 · [QA/P0] Three unit suites are declared coverage that no runner has ever executed

**Discovered by measurement this session, not from the board.** `package.json` declares
`test:unit` over five spec files, but:

- `build:check:steps` (480 steps) runs exactly one `node --test` step, covering only
  `tests/worker.unit.spec.js` and `tests/obelisk-auth.unit.spec.js`.
- `npm run test:unit` is invoked by **nothing** — not `run-build-check.mjs`, not any
  workflow in `.github/workflows/`.

So `tests/tt-report-only.unit.spec.js`, `tests/resync-derived.unit.spec.js` and
`tests/local-preview.unit.spec.js` — 16 tests — are gated by no runner at all. Run
directly this session they pass 16/16, so this is not a red being hidden; it is a
regression alarm that was never armed. A gate no runner invokes has never run.

**Do:** extend the existing `node --test` step in `build:check:steps` to all five files so
the declared set and the executed set are the same set, and keep `test:unit` in sync.

## 3 · [DATA/P1] `build-brand-assets.mjs` writes a manifest that omits every skipped job

**The row S350's handoff explicitly owed, now filed and fixed.** Verified live:
`scripts/build-brand-assets.mjs:74-77` returns early when `job.src` is missing, logging
`⊘ skip (missing source)`; `:116` then writes `brand/assets.json` unconditionally from
whatever accumulated. A run where every master is absent therefore replaces a correct
7-entry manifest with `"assets": []` and exits 0.

This is not hypothetical — it happened in S350 under `resync-derived --sweep-repair` and
was caught only by `build:check` step 111 (`--check` drift), one step short of being
committed. The generator is the wrong place to be silent: `--check` catches the damage
after the fact, but the writer should refuse to produce a manifest it knows is incomplete.

**Do:** count skipped jobs; if any job was skipped, refuse to write the manifest and exit
non-zero naming the missing sources. A partial manifest must never be presentable as a
complete one.

## 4 · [OPS/P3] Self-test the stale-shell matcher so it cannot go dead silently again

Carried from S350 `[S350][SIL][OPS/P3]`, premise re-verified: `scripts/clean-stale-shells.mjs`
has no `--self-test` and its matching logic (`liveHashes()`, `shellFiles()`, and the
`shell-([a-f0-9]+)\.js$` predicate) is module-private, so nothing can assert it against a
known-stale name. S350 root-fixed a regex in this file that had never matched; the defect
class is "the cleaner silently matches nothing", which only a synthetic fixture can catch.

**Do:** export the pure predicate, add a `--self-test` that asserts a synthetic stale name
is classified stale and a referenced one is classified live, and wire it into `build:check`.
