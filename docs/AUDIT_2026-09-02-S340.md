## A1 · [CI/P0] The E2E Test Suite has been dead on every push for 17+ hours, and the fix S338 shipped covered only half the class

**Verified live.** `gh run list --workflow="E2E Test Suite"` — **8 consecutive failures**, unbroken since
`2026-09-02T06:34Z`. Both jobs (`e2e` and `compliance`) die at the same step, `HTTP smoke pre-gate`:

```
✗  /vaultsparked/   status: expected 200, got 404   missing: "Membership tiers moved"
✗  /ranks/          status: expected 200, got 404   missing: "Vault ranks moved"
10 passed, 2 failed
```

`scripts/smoke-http.mjs:60,65` asserts both routes return **200 with the body of a stub page that S335
deleted**. Both are `from` entries in `config/route-consolidation.json`. The smoke runs against
`local-preview-server.mjs`, which serves the built tree with no edge layer — so the `_redirects` 301 that
answers these routes in production **cannot apply**, and the assertion is a guaranteed 404 there.

**This is the exact class S338 closed — for a different consumer.** `check-workflow-audit-targets.mjs`
enforces "no consolidated route is an audit target" and "every local-preview target must resolve to a page",
and it is green, because its subject is **absolute URLs and `for u in` loops inside workflow YAML**. The
routes that killed E2E are bare path literals one hop in, inside a script the workflow invokes by name. A
detector blind to helper indirection reports clean while the defect it was built for runs in the next file.

**Blast radius is larger than the symptom, and masked by it.** The smoke is a *pre-gate*: it exits 1 before
Playwright runs, so every consumer behind it is untested and unreported. Fixing only the smoke unmasks a
second wave. Live grep of consolidated routes actually navigated against `BASE`:

| Consumer | Route |
|---|---|
| `tests/s103-surfaces.spec.js:19` | `/vaultsparked/` |
| `tests/vaultsparked-csp.spec.js:31` | `/vaultsparked/` |
| `tests/pages.spec.js:37` | `/ranks/` |
| `tests/cls-regression.spec.js:39,40` | `/ranks/`, `/join/` |
| `tests/light-mode-screenshots.spec.js:11` | `/ranks/` |
| `tests/intelligence-surfaces.spec.js:11,64` | `/join/` |
| `tests/micro-feedback.spec.js:8` | `/join/` |
| `scripts/check-render-blocking-routes.mjs:57` | `/vaultsparked/` |

**Root cause, and the fix that closes all of it at once.** `local-preview-server.mjs` already parses
`_headers` on purpose — its own comment says *"matching what the real CDN sends — keeps synthetic scores
representative"*. The redirect half of that fidelity was never written. Teaching the preview `_redirects`
makes it faithful to the edge, and every stranded consumer — smoke, eight specs, Lighthouse, accessibility —
resolves at once, permanently, including every future merge, because `_redirects` is generated from
`config/route-consolidation.json`.

**Fix:** (1) preview server honours `_redirects` with Cloudflare's precedence and `:splat` semantics;
(2) `smoke-http.mjs` asserts the **301 contract** for consolidated routes instead of a deleted stub's body.

## A2 · [CI/P1] Gate the class at the level it actually occurs: follow the workflow → script edge

**Verified.** `extractTargets()` reads workflow text only. `smoke-http.mjs`'s route table is invisible to it,
which is why A1 could happen with the S338 gate green. This is the third time a route list has been stranded
by a merge (Lighthouse S338, smoke S340) and the second time a gate missed it by scope rather than by logic.

**Fix:** resolve the invocation edge — for each workflow, follow `node scripts/<x>.mjs` into the script and
subject any declared route-assertion table to the same two rules, with the job's local-preview provenance.
Make the *edge*, not a list of scripts, the thing the gate follows.

## A4 · [BUILD/P2] The postbuild ordering question — instrumented, not grepped

**Carried with its method, twice.** S339 tried static classification of the 23 `postbuild` steps and was
wrong in both directions: page writes go through helpers. The honest instrument snapshots rendered-page
mtimes between steps, derives the writer set and the hasher set empirically, then asserts every hasher runs
after the last writer. S339 deferred it because it perturbs the build being converged for a deploy.

**Sequencing that resolves the deferral rather than repeating it:** run the instrumented probe *before* any
convergence work, then let the final `npm run build:check` be a clean run on a frozen tree. The deferral's
premise was a scheduling conflict, not an impossibility.
