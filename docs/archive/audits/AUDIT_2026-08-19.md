## P0

### 1. [SECURITY/P0] The S319 crash fix hardened only `startLogin`; the callback and logout legs keep the identical unguarded KV write

**Evidence (live code, this session):**
- `cloudflare/obelisk-auth.js:662-663` — `finishLogin()` calls `await env.RATE_LIMIT.get(...)` and
  `await env.RATE_LIMIT.delete(...)` **before** the `try` block that begins at line 681.
- `cloudflare/obelisk-auth.js:979` — the `/api/auth/logout` branch calls
  `await env.RATE_LIMIT?.delete(...)` with no enclosing `try`.
- `cloudflare/security-headers-worker.js:883` — `async fetch(request, env, ctx)` has **no top-level
  `try`/`catch`** (verified across all 1345 lines: no outer `try` before the call, no `catch` at the
  tail — the handler ends `return finalResponse; },` at 1343).
- `cloudflare/security-headers-worker.js:935` — `handleObeliskAuthRequest` is awaited bare.

**The class.** S319's own comment at `obelisk-auth.js:599-608` states the rule correctly: *"a dependency
being down is a KNOWN state, not an unhandled error."* That rule was applied to `startLogin` and stops
there. `.delete()` is a KV **write**, so the exact free-tier quota exhaustion that produced the S319
outage rejects at line 663, the rejection escapes `finishLogin` → escapes `handleObeliskAuthRequest` →
escapes `fetch` → Cloudflare returns **1101 / HTTP 500**.

**Why it is worse than the leg already fixed.** `/auth/callback` is reached *after* the member has
completed the passkey ceremony at the provider. A crash there burns a successful authentication and
strands the flow record; `/login` at least failed before the user spent anything.

**Conversion outcome:** a member who authenticates successfully lands on a working page instead of a
bare Cloudflare 500 — this is the last mile of the sign-in conversion path.

**Action:**
1. Move the `get`/`delete` pair inside a guard that returns the same honest named 503 shape
   (`auth_store_unavailable`) the start leg already uses.
2. Same guard on the logout `delete`.
3. Add a last-resort `catch` in the Worker `fetch` handler that logs and returns an honest 503 rather
   than a bare 1101 — **not** a silent swallow: it must `console.error` with the route so the failure
   stays observable (CANON-031).
4. Unit tests asserting each leg returns a named 503, not a throw, when KV rejects.

### 2. [TRUTH/P0] The public status surface tells visitors sign-in is broken while sign-in works

**Evidence:**
- `GET /login` → 302 with a full PKCE authorize URL (measured above). Sign-in is **working**.
- `context/PROJECT_STATUS.json` → `publicNote`: *"Sign-in is briefly unavailable and says so plainly;
  it restores automatically at the next daily reset."*
- `api/nervous-system.json` → `focus` carries the same sentence, **published**.
- `blockers[0]` still asserts the 503 as current.

**The class.** This is the honest-dark pattern inverted: the surface was correctly built to admit
degradation, but nothing retracts the admission when the degradation ends. A stale pessimistic claim
is as much an observability lie as a stale optimistic one, and it costs more here — it sits on the
join path.

**Conversion outcome:** removes an active deterrent from the member sign-up path; a visitor reading
the status surface is no longer told the thing they are about to use is down.

**Action:** correct `publicNote`, `blockers`, and `currentFocus` from the live probes, regenerate
`api/nervous-system.json`, and land item 3 so this cannot silently recur.

### 3. [GATE/P0] `check-public-note-freshness.mjs` contains no freshness check

**Evidence (live code):** the file is 72 lines. Its only assertions are three regexes —
`SESSION_CODE`, `BRACKET_NOTATION`, `DEV_JARGON` (lines 25-27) — applied by `checkField()` to
`publicNote` and `publicNextStep`. There is no timestamp read, no age comparison, and no corroboration
against any live receipt. It measures **voice**, not freshness.

**Proof it is inert against the real defect:** it exits 0 right now, on the false outage claim in item 2.
The claim is plain English and jargon-free, so every assertion it owns passes.

**The class.** A gate whose name promises a property it never measures reads exactly like a passing
gate — the same failure shape as a probe that only exercises the healthy branch. The name is why
nobody looked here for twenty sessions.

**Info-finding outcome:** the public status surface stops being able to publish a stale claim about a
degradation that has ended — readers get a status that is true, not merely well-worded.

**Action (structural, not an allowlist):** extend the gate so that when `publicNote`/`blockers` assert
a **degraded** state (a small vocabulary: `unavailable`, `down`, `outage`, `briefly`, `degraded`,
`503`), the assertion must be corroborated by a live receipt no older than a bounded window; an
uncorroborated degradation claim fails. Rename to reflect what it now checks. Self-test **both**
directions (a true degradation claim passes; a stale one fails) — a gate that can only go red on the
degraded branch is the bug in item 3 all over again.
