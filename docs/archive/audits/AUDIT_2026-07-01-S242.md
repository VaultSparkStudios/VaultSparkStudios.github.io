## Obelisk Answer

We have not integrated Obelisk fully because the repository is in the posture it documents: **phase-0 declared, Obelisk-ready, not Obelisk-active**.

Current truth:
- `assets/identity.js` is an abstraction layer, but `ObeliskProvider.isReady()` returns `false` and every Obelisk method returns `obelisk_not_ready`.
- `vault-member/portal.js` and related member/investor surfaces still make direct `VSSupabase.auth.*` calls.
- Supabase row-level-security policies depend on `auth.uid()`, so an Obelisk session must mint or bridge to a compatible Supabase JWT before protected member data can work.
- The Obelisk callback existed but had no Worker route; that is now fixed as a fail-closed `/api/obelisk-verify` route.
- The verifier secret/capability is not available locally, so a real positive verification path cannot be truthfully enabled in this repo today.
