## TIER 1 — Conversion-honesty root-fix  *(P0)*

### 1. [HONESTY·CONVERSION] Dead-CTA detection has no recency epoch — `score 95`
**Live evidence.** `api/dead-ctas.json` has flagged `play-next` (cross-game play-next card) as **dead** (18 shown / 0 clicks) every session since S207. But the detector (`check-dead-ctas.mjs` → reads `api/funnel-summary.json` `families[]`) sums impressions over the **entire 30-day window** with **no lower bound at the CTA's last material change**.

**Why it's a false signal.** The play-next card was **retimed in S207** (commit `2aa59982`, **2026-06-18**) — reveal-on-engagement + completion-framed copy, replacing the dead S206 above-the-fold variant. The current `funnel-summary.json` only reflects RUM history through **2026-06-14** — i.e. **all 18 impressions predate the retiming**. The retimed copy has *zero* measured impressions, yet it is judged "dead" on the old variant's data. Rotating the copy now (`build-cta-state --advance`) — as the S207 measure-watch tentatively suggested — would burn the variant-0 measurement window on a verdict derived from pre-fix data (exactly what D-S207.2 warns against).

This is the **same class** as the S208 perf-budget staleness bug ([[feedback_perf_budget_window_needs_recency_bound]]): a rolling-N aggregate with no recency horizon fails a *resolved* item forever. The `funnelCtas[]` path already uses 7-day windows; the `families[]` path does not.

**Fix.** Add an optional per-family **recency epoch** to `rollup-rum-ux.mjs` `deriveSummary()`. When a family declares `epoch`, only count impressions on/after that day (the epoch only *tightens* the window, never widens past `WINDOW_DAYS`). Set `play-next` epoch = `2026-06-18`. Surface `since` on the family so the windowing is honest/visible. Add a **control self-test** proving the epoch flips the verdict (pre-epoch impressions → `counts.shown = 0` → not dead).

**Result.** `play-next` drops off the dead-CTA list — replaced by the honest state "insufficient post-retiming impressions" — and the rotation question is answered correctly: **do not rotate yet.**
