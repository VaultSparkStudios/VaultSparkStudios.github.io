## P0

### 1. [TRUTH/P0] Three tracked public feeds are stale and their gates are red-but-unread

**Evidence (live, this session):** the three exit-1 rows above.

- `api/changelog-narrative.json` — the plain-English public changelog. 22 committed entries; the
  source `api/commit-map.json` now yields 23. The newest shipped work is **missing from the public
  changelog**.
- `api/intent-map.json` — the outcome-to-route-to-evidence map. This is a **CANON-048 dual-audience
  surface**: the machine-readable answer to "where do I go to do X" that agents read. A drifted intent
  map points agents at routes derived from stale evidence.
- `data/stats-surface.json` + `stats.json` — the **CANON-054 public stats surface**, the thing the
  site uses to report its own numbers.

**Info-finding outcome:** a reader or an agent asking "what shipped recently", "where do I go to
verify a claim", or "what are this studio's numbers" currently gets an answer one build behind, on
three separate surfaces, with no signal anywhere that it is behind.

**Action:** regenerate all three; commit the regenerated artifacts.

### 2. [GATE/P0] `build-release-dependencies --check` reports `rejected` and exits 0

**Evidence:** `scripts/build-release-dependencies.mjs:154-163`. The `--check` branch parses the
receipt, runs `validateReceipt()` (shape only), prints the state and falls off the end of the `try`.
`state` is one of `completed | pending | rejected` (line 132: `rejected` when any dependency is
`missing | invalid | expired`). The live run prints
`build-release-dependencies --check: rejected · obelisk-staging-registration:missing` and **exits 0**.

This is the S323 defect class one level up: the gate is named `--check`, but its body validates only
that the receipt is *well-formed*, never that it is *satisfied*. A well-formed rejection is a pass.

**Outcome:** the release-dependency handshake — the thing meant to hold a release when a declared
cross-repo dependency is missing — cannot hold anything.

**Action:** exit 1 on `state === 'rejected'`. Keep `pending` non-blocking (an honest in-flight state,
not a failure). Lock both directions with a self-test.

### 3. [GATE/P0] `build-stats-surface --check` fails as an uncaught stack trace

**Evidence:** `scripts/build-stats-surface.mjs:144` — `writeOrCheck()` throws a bare `Error` at module
top level. The operator-visible output is nine lines of `at ModuleJob.run` ending in
`Node.js v24.14.0`; the actual message scrolls off the top. Any log-tailing runner records the Node
version as the failure reason.

**Action:** honest one-line failure and non-zero exit, no stack.

## P1

### 4. [GATE/P1 · STRUCTURAL] Nothing prevents the next `--check` gate from being born unreachable

Fixing the twelve is a list. The list will rot: the next `build-*.mjs` shipped with a `--check` and no
runner line is silently unmeasured from birth, and `build:check` will still say all-green.

Structural gates beat hardcoded exception lists. The durable fix is a **reachability meta-gate**:
enumerate git-tracked `scripts/build-*.mjs` supporting `--check`, resolve the full runner graph
(`build:check:steps` union `check-proof-surface` `STEPS`/`ADVISORY_STEPS` union
`check-generated-drift-preflight`), and fail when any `--check` gate has no runner. Documented
dry-runs (a `--check` that means "report what would render") declare themselves and are exempt by
declaration, not by name.

Gates must enumerate **git-tracked** files, not walk the filesystem.

### 5. [GATE/P1] Wire the six green-but-unmeasured gates into the run

`build-launch-age`, `build-oracle-velocity-public`, `build-rank-climbers`, `build-tt-summary`,
`build-ecosystem-stats-page`, `build-ecosystem-bridges` are green today. Green today is not a reason
to leave them unmeasured — that is precisely the state the other three were in before they went red.
