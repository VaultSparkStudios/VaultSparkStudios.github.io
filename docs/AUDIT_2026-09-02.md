## A1 · [DEPLOY/P0] The origin the release ceremony verifies against has no publisher

**Verified.** `grep` across `.github/workflows/` returns **zero** invocations of `scripts/deploy-staging-content.mjs`. The
only automation-shaped reference is the npm alias `deploy:staging:content`, which nothing calls — the "a gate living in an
uncalled npm script has never run" shape, applied to a *deploy lane* rather than a check. `pages-deploy.yml` and
`cloudflare-worker-deploy.yml` both name `https://website.staging.vaultsparkstudios.com` — but only as a `--url` the
release ceremony **reads**. Nothing in this repo has ever **written** to it on a schedule or on a lane.

Live probe: staging `api/build-sha.json` = `94e78e93…`, `builtAt 2026-08-28T09:58:13Z`, `deployedBy: "full-build"` —
a hand run, five days stale, and the newest of exactly two hand runs on record (the other is S312, 2026-08-11).

S338 correctly *measured* the drift (23 advertised routes behind) and correctly declined to gate on it. It recorded the
cause as unknown — "find what deploys the Hetzner staging origin and why it stopped". The answer is that **nothing ever
did**; there was no publisher to stop. CANON-007 says staging is the thing production is verified against, so the release
ceremony has been clearing a tree five days newer than the one it measures.

**Fix (three parts, in order):**
1. **Try-first (CANON-019):** `hetzner.ssh` is `✓ READY 2/2`. Run the overlay against the served baseline now and bring
   staging current. This is agent work, not a founder action.
2. **Wire the publisher** so the drift cannot silently resume.
3. **Structural gate, naming no origin:** *every origin a release workflow names as a verification target must have a
   publisher reachable from this repo.* The class — not this instance.

Then flip `surfaceParity.gating` to `true` once `state` reads `matched`.

## A2 · [OBS/P1] Audit every receipt round trip for the D-S338.1 lossy-reader class

**Verified as a repeat.** S338 fixed `observationFromReceipt()` dropping three S336 fields — the **third** time a field was
added to an emitter and forgotten in its reader (`retainedForHours` S300, `historyComplete` S316, the content clock S336).
The S300 test of exactly this shape stayed green throughout because its fixtures omitted the dropped fields: a fixed-point
test is only as wide as its fixture. S338 closed it for one receipt with a field-naming-free property
(`derive(read(derive(x))) === derive(x)`). Every other receipt with a derive/read pair is still on the old footing.

**Fix:** enumerate the derive/read pairs, apply the same property to each, and make the *property* — not a list of
receipts — the thing the gate enforces.

## A3 · [BUILD/P2] Audit the whole `postbuild` chain for the D-S338.4 ordering class
