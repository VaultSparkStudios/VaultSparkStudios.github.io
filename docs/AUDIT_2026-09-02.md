## Ranked items

### 1. [DEPLOY/P0] Run the full production deploy. It is not blocked — the board says it is.
**Priority 100.** The task board records the full `confirm_production` deploy as "gated on the Obelisk
identity hold", and `PROJECT_STATUS.json` carries the same claim in two blockers. That was true until S319.
Measured this session:

```
node scripts/check-promotion-scope.mjs --check
  → promotion-scope: promotable=true · scoped-disjoint

  node scripts/check-production-promotion-gate.mjs --emit-github-output
  → allowed=true; mode=scoped; state=hold; reasons=real-provider-e2e-pending;
    held=auth/**,identity,worker:identity
```

The S319 SCOPED path (D-S319.2, founder-authorized) permits promotion when the candidate leaf set is
provably disjoint from the held blast radius. It currently is. The hold is *not* cleared, weakened or
edited by using it — `releaseState`, `hold` and `reasons` stay byte-identical, and `auth/**`,
`surface:identity` and `worker:identity` stay held and named on the public receipt.

**First step:** `gh workflow run pages-deploy.yml -f confirm_production=true`, then probe the apex for the
new build sha and re-derive `api/deploy-currency.json`.

### 2. [DEPLOY/P1] Retire `vault-wall/` from `config/served-surface.json` once the deploy has removed it.
**Priority 62.** Held in S336 (D-S336.2) because the content lane cannot delete files or promote
`_redirects`, so production still serves `/vault-wall/` and the deployed sitemap still advertises it. At
HEAD the prefix matches nothing and is inert. Item 1 is exactly the deploy that retires it. **First step:**
after item 1 lands, probe `/vault-wall/` for a 301/404 and confirm the deployed `sitemap.xml` no longer
lists it; only then remove the prefix and re-run `prune-served-surface --check`.

### 3. [TRUTH/P1] Correct the stale "full deploy is identity-blocked" claim wherever it is published.
**Priority 58.** Three surfaces assert a blocker that stopped being true 18 sessions ago: the S336 DEPLOY/P3
board item, and two `PROJECT_STATUS.json` blockers. This is the exact failure class CANON-031 exists for and
that S321 already paid for once — a hand-maintained sentence about a hold, outliving the hold. **First
step:** rewrite all three to state what is actually held (the identity blast radius) and what is not
(everything else, promotable by the scoped path), and record the correction in `TRUTH_AUDIT.md`.

### 4. [OBS/P2] `news-publish.yml` cannot tell a radar crash from an empty queue.
**Priority 44.** Verified at `.github/workflows/news-publish.yml:91`:
`node scripts/news-trend-radar.mjs --scan || echo "trend radar produced no new corroborated topics"`.
A genuine crash and a legitimate zero-topic result produce an identical green step; the failure then
resurfaces one step later as the misleading `✗ no topic queue`. **First step:** have `--scan` emit
`items/topics/queued/rejected` as GitHub step outputs and branch the message on the real exit code, so an
empty queue states its own cause and a crash is visibly a crash.

### 5. [NEWS/P2] Fact extraction scores advertising copy as a sourced fact.
**Priority 41.** `factCandidates` (`scripts/news-draft-edition.mjs:84`) scores digits (+3), proper nouns
(+1) and reporting verbs (+2), and penalises marketing pronouns and CTAs — but nothing ties a sentence to
the story. The 2026-08-31 edition's first fact was a syndicated Shark vacuum promo block, rendered as a
cited fact under a real publisher URL. Score under the current rubric: +4, no penalty. This is a public
truth defect, not a cosmetic one. **First step:** add a topical-relevance term to the score — penalise
sentences sharing no significant token with the headline or topic title — and cover it with a self-test
carrying the real promo sentence as the negative case.

### 6. [NEWS/P2] The published edition does not record which model wrote it.
**Priority 38.** `desk-inference.mjs:200` sets `fellBackFrom` whenever a standby authors, precisely so the
caller can disclose it — and `authorDraft` (`author-news-edition.mjs:327`) returns
`{ok, attempt, draft, findings}`, dropping both `result.model` and `result.fellBackFrom` on the floor. The
day artifact's keys are `date/simulated/leadSlug/stories`; no story records a model. With the preferred
model depooled, editions are almost certainly standby-authored, and the `/news/` editorial disclosure
therefore states an assumption where it should state a fact. **First step:** thread `model` and
`fellBackFrom` through `authorDraft` into the draft and the day artifact, and surface the authoring model
on the disclosure block.
